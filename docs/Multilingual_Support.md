# chabo-dsl、多言語対応できるんじゃね？

chabo-dslは、Perlでゼロから作っている小さなDSLです。

現在は日本語DSLを実装しています。

……が、ある日ふと思いました。

> **これ、日本語じゃなくてもいけるんじゃね？**

私は日本語しか話せません（笑）。

なので英語、韓国語、中国語、ましてやアラビア語なんて、正直よく分かりません。

でも、chabo-dslの内部構造を考えてみると、**言語そのものに依存している部分と、言語に依存していない部分がかなりきれいに分かれている**ことに気付きました。

---

## Ast.pmは自然言語を知らない

chabo-dslの中心にある `Ast.pm` は、基本的に自然言語を知りません。

たとえば、

```text
(年齢 >= 18) ? 成人 : 未成年
```

という式が渡されれば、それをASTとして解析して評価できます。

ここで重要なのは、

```text
年齢
成人
未成年
```

が日本語だからといって、Ast.pmが日本語を理解しているわけではない、ということです。

Ast.pmから見れば、これらは単なる**識別子や値**です。

つまり、

```text
Age
Adult
Minor
```

でも、

```text
나이
성인
미성년자
```

でも、

```text
年龄
成年人
未成年人
```

でも、基本的には同じように扱えます。

---

# じゃあ、自然言語の部分はどこにある？

そこで登場するのが `Sugar.pm` です。

日本語DSLでは、

```text
もし年齢が18以上なら成人以外未成年
```

のような、人間が読みやすい日本語を、

```text
(年齢 >= 18) ? 成人 : 未成年
```

のようなAst.pmが理解できる式へ変換します。

つまり、

```text
人間が書く言葉
       ↓
    Sugar.pm
       ↓
chabo-dslの共通表現
       ↓
     Ast.pm
       ↓
      実行
```

という構造です。

この「Sugar.pmとAst.pmの分離」が、もしかすると結構面白いことにつながります。

---

# もしかして英語でもいける？

例えば英語用のSugarを作ったとします。

入力：

```text
If Age is greater than or equal to 18 then Adult else Minor
```

Sugar変換後：

```text
(Age >= 18) ? Adult : Minor
```

あとは日本語の場合と同じです。

Ast.pmは、

> 「英語？ 何それ？」

という感じで、そんなことは気にせずASTを作って評価します。

---

# 韓国語なら？

例えば、

```text
나이가 18 이상이면 성인 아니면 미성년자
```

を、

```text
(나이 >= 18) ? 성인 : 미성년자
```

に変換できれば、

これもAst.pmに渡せます。

---

# 中国語なら？

例えば、

```text
如果年龄大于等于18则成年人否则未成年人
```

を、

```text
(年龄 >= 18) ? 成年人 : 未成年人
```

へ。

これもいけそうです。

---

# そしてアラビア語……

ここまで来ると、ちょっと調子に乗ってきます（笑）。

例えば、

```text
إذا كان العمر أكبر من أو يساوي 18 فبالغ وإلا قاصر
```

を、

```text
(العمر >= 18) ? بالغ : قاصر
```

に変換できたとします。

すると……

**Ast.pmはこれも特に気にしません。**

日本語だろうが、

```text
年齢
```

英語だろうが、

```text
Age
```

韓国語だろうが、

```text
나이
```

中国語だろうが、

```text
年龄
```

アラビア語だろうが、

```text
العمر
```

Ast.pmから見れば、全部「変数名」です。

---

# 実はUnicode変数名に対応している

ここで効いてくるのが、Ast.pmの変数名の定義です。

```perl
VAR_NAME => qr/[\p{L}_][\p{L}\p{N}_]*/u
```

`\p{L}` はUnicodeの文字、`\p{N}` はUnicodeの数字です。

そのため、例えば、

```text
年齢
Age
나이
年龄
العمر
```

のような変数名を扱える設計になっています。既存の言語リファレンスでもUnicode変数名がchabo-dslの機能として整理されています。

つまり、

```text
年齢 = 20
Age = 20
나이 = 20
年龄 = 20
العمر = 20
```

のようなコードも、**変数名の部分については同じASTエンジンに載せられる可能性があります。**

---

# Sugar.pmが「翻訳者」になる

こう考えると、Sugar.pmの役割がちょっと面白く見えてきます。

Sugar.pmは、言語そのものを実行する処理系というより、

> **人間の言葉を、Ast.pmが理解できる共通言語へ翻訳する層**

と考えることができます。

例えば、

```text
日本語
  ↓
Sugar.ja.pm
  ↓
(年齢 >= 18) ? 成人 : 未成年
  ↓
Ast.pm
```

英語なら、

```text
English
  ↓
Sugar.en.pm
  ↓
(Age >= 18) ? Adult : Minor
  ↓
Ast.pm
```

韓国語なら、

```text
한국어
  ↓
Sugar.ko.pm
  ↓
(나이 >= 18) ? 성인 : 미성년자
  ↓
Ast.pm
```

という感じです。

**最後に待っているAst.pmは全部同じ。**

ここが面白いところです。

---

# 「言語」と「処理系」を分離できる

つまり、極端に言えば、

```text
         日本語
           │
       Sugar.ja
           │
           ↓
        ┌─────┐
英語 →  │     │  ← 韓国語
       │Ast.pm│
中国語→ │     │  ← アラビア語
       └─────┘
```

という構造にできます。

新しい言語を追加するときも、Ast.pmを改造するのではなく、

**その言語をAst.pmの共通表現に変換するSugarを追加する。**

という考え方です。

---

# もちろん、これはまだ「妄想」です（笑）

ここは大事なところです。

今回の英語、韓国語、中国語、アラビア語の例は、**各言語版のSugar.pmを実装したわけではありません。**

あくまで、

> 「Ast.pmが自然言語に依存していないなら、Sugar.pmを言語ごとに作れば、多言語DSLにできるんじゃないか？」

という設計上の可能性を試しに考えてみたものです。

実際にやるとなると、

* 各言語の構文解析
* 語順
* 助詞や前置詞
* 活用
* 複数形
* 文字列リテラル
* コメント
* 演算子の表現
* 文の区切り
* 関数名
* エラーメッセージ

など、いろいろ考える必要があります。

特にアラビア語まで行くと、私は完全にお手上げです（笑）。

---

# それでも、この設計はちょっと面白い

chabo-dslを作っていて面白かったのは、

**「日本語でプログラムを書く」ことそのものよりも、日本語部分を取り除いてみると、意外と普通の言語処理系になっていた**

ということです。

日本語DSLは、

```text
Sugar.pm
```

という「見た目」の部分。

その下には、

```text
Tokenizer
Parser
AST
Evaluator
Scope
Function
```

という、自然言語とは関係のない処理系があります。

実際、chabo-dslのREADMEでも、日本語DSLはSugar.pmとして実装され、エンジン本体は自然言語に依存しないという設計になっています。

だから、

> **日本語DSLを作ったつもりが、実は「多言語DSLの土台」を作っていたのかもしれない。**

……なんてことを、ちょっと考えてしまいました。

まだ実験段階ですけどね（笑）。
